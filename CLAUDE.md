# Портфолио — Анастасия Плетнер (Pletner Design)

Личный дизайн-портфолио на React 19 + TypeScript + Vite. Витрина концептов
UI/UX-проектов ("Аптеки рядом", "HackWish", "Movie Mate", "CampaignCore").
Визуальный стиль — коллаж/скрапбукинг (вырезки из бумаги, нитки, звёзды).

## Структура

- `src/components/Header`, `src/components/Footer` — общий каркас (шапка с лого, футер со ссылками)
- `src/pages/Main` — главная: `Hero` (о себе) + `MainContent` (грид проектов)
- `src/pages/ProjectPage` — страницы отдельных кейсов (Apteki, Dashboard и т.д.)
- `src/data.ts` — список проектов для карточек на главной
- `src/UI` — общие компоненты (`Button`) и `sharedStyles.module.css` (обёртки, отступы, акцентный цвет)
- CSS Modules везде, без глобального стейт-менеджмента

## Известные особенности / договорённости

- Карточка HackWish в `data.ts` временно ведёт на `AptekiPage` (своей
  страницы ещё нет) — осознанная временная заглушка, не трогать без явного
  запроса. Movie Mate теперь имеет свою страницу (`MovieMatePage`, см. п.24
  ниже) — `AptekiPage` в `data.ts` всё ещё импортируется ради HackWish, не
  убирать импорт.
- Раздел с проектами (`data.ts`, `Project.tsx`, страницы кейсов) — просили не
  ломать при переделке хиро-секции; трогаем только раскладку грида, не контент.
- Header **не** fixed (по просьбе — не должен залипать при скролле), фон
  header и фон страницы — один и тот же `var(--color-bg)`, чтобы не было шва.
  `.paddingTop` в `sharedStyles.module.css` теперь просто фиксированный
  небольшой отступ (40/20px по брейкпоинтам), не завязан на высоту header.
- Акцентный цвет вынесен в CSS-переменные в `src/index.css` (`--color-accent`,
  `--color-accent-dark`, `--color-accent-tint`) — сейчас розовый (#C04A6E),
  подобран по цвету кружочков на фото в Hero (сэмплировано скриптом из пикселей
  картинки). Менялся несколько раз по ходу правок — если попросят другой
  оттенок, смотреть на эти три переменные.
- Текстура фона (`body::before` в `index.css`) — реальное фото мятой бумаги
  (`public/image/paper-texture.png`), скачано с Unsplash (свободная лицензия,
  без атрибуции) с явного разрешения пользователя, обработано локально
  (Python/PIL): high-pass фильтр выделяет только заломы, из яркости сделан
  альфа-канал → полупрозрачный PNG на тёмно-бежевый цвет, `mix-blend-mode:
  multiply` + `opacity: 0.45` для мягкости.

27. **Важный gotcha, найденный при проверке п.26**: `.screenHeading`/
    `.prototypeHeading` из п.26 сначала НЕ сработали (margin-bottom
    оставался 8/12px вместо 20px) — не кэш браузера (проверила через
    `getComputedStyle`/`getBoundingClientRect` после хард-рефреша), а
    реальный проигрыш по CSS-специфичности. В `src/pages/ProjectPage/page.css`
    (обычный CSS, не модуль, импортится один раз в `LayoutProject.tsx` и
    действует на ВСЕХ страницах кейсов) есть глобальные `.projectPage h1`,
    `.projectPage h2/h4/h5`, `.projectPage h3` с своими `margin-bottom`.
    Специфичность `.projectPage h3` = (0,1,1) выше простого классового
    селектора вроде `.screenHeading` = (0,1,0) — поэтому любой класс из
    CSS-модуля страницы, который переопределяет margin у h1-h5 внутри
    кейса, **надо** писать как `:global(.projectPage) h3.имяКласса` (или
    аналогично под нужный тег), а не просто `.имяКласса`. Если на любой
    другой странице кейса понадобится поменять отступ у заголовка — сразу
    проверять на этот конфликт (см. пример в `moviematePage.module.css`).
28. **Правка после ревью (3)**: отступ между разделителем под "UI/UX-дизайн и
    кликабельный прототип" и заголовком "Приветственный экран, вход и
    регистрация" был 40px вместо нужных 20px — `.screenSection` (margin-top
    40px, п.26) была ошибочно навешена и на этот блок тоже. У него margin-top
    не нужен: сверху уже есть `margin-bottom: 20px` от `.prototypeHeading`, а
    т.к. margin-collapsing между соседними блоками берёт МАКСИМУМ, а не сумму,
    20 и 40 схлопывались в 40. Убрала `moviemateStyles.screenSection` с блока
    "Приветственный экран..." (оставила только на "Онбординг"/"Основные
    экраны", где до них действительно предыдущий блок — картинка, а не
    заголовок с собственным отступом). Стоит помнить при похожих правках:
    margin-top на блок ПОСЛЕ заголовка с margin-bottom — коллапсится, а не
    складывается, проверять итоговый зазор через `getBoundingClientRect`,
    а не гадать по сумме объявленных значений.
29. **Тот же класс gotcha (п.27), но обратный случай** — на странице
    Dashboard (`dashboardPage.module.css`) отступ между "О проекте"/"Что
    было сделано"/"Результат" и текстом под ними был 24px вместо
    заказанных 12px: `.textBlock` даёт `gap:12px` (flex), а глобальный
    `.projectPage h2 {margin-bottom:12px}` из `page.css` добавляется
    ПОВЕРХ гэпа (margin и flex-gap не взаимоисключающие, а складываются —
    в отличие от margin+margin, которые схлопываются, см. п.28). Обнулила
    явно: `:global(.projectPage) .textBlock h2 { margin-bottom: 0; }`.
    **Правило на будущее для любой страницы кейса**: если контейнер уже
    использует `gap` для отступа между заголовком и текстом, margin-bottom
    у самого заголовка (из глобального `page.css`) нужно обнулять отдельно
    — иначе гэп и margin сложатся. Проверять через
    `getComputedStyle(el).marginBottom` + `getBoundingClientRect()`,
    не полагаться на визуальный скриншот.
30. Кнопки в Hero поменяны местами: теперь "Посмотреть CV" (с бордером)
    слева, "Пригласить на собеседование" (акцентная) справа — было
    наоборот. Отступ под Hero увеличен ещё раз: 130→170px десктоп,
    80→100px планшет, 64→80px мобилка.
31. `html` не имел своего `background-color` (только `body`) — на коротких
    страницах/при overscroll-отскоке скролла (особенно на macOS трекпаде)

    `html { background-color: var(--color-bg); }` в `index.css`, рядом с
